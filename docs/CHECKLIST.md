# 개발 과정 체크리스트

[PRD](PRD.md) 기반. 2026-11-02에 **API 키를 받을 수 없어** 수집 방식을 보고서 업로드(드롭 폴더)로 바꿨다. 단계 순서는 유지하되 0~2단계를 이에 맞게 고쳤다.

**표기**: `[x]` 완료 · `[~]` 코드 작성됨, 실제 환경 미검증 · `[ ]` 미착수 · `[-]` 보류(API 방식, 키 확보 시)

| 단계 | 내용 | 완료 조건 |
| --- | --- | --- |
| 0 | 사전 준비 | 샘플 보고서 확보, 필드·보고서 컬럼 확정 |
| 1 | 시트와 설치 | 5개 탭 생성, 메뉴 동작 |
| 2 | 수집 (보고서 업로드) | 업로드한 보고서의 소재별 노출·클릭이 원본 탭에 쌓임 |
| 3 | 매핑과 판정 | 판정 탭 자동 갱신 |
| 4 | 트리거와 알림 | 월요일 알림 수신 |
| 5 | AI 개선안 | 알림에 AI 개선안 포함 |
| 6 | 운영 점검 | 성공 기준 점검, Phase 2 결정 |

---

## 0단계: 사전 준비

- [x] 공식 API 문서로 인증·엔드포인트·필드명 조사 → [STAGE0_FINDINGS.md](STAGE0_FINDINGS.md)
- [x] 성과형 디스플레이 API 조사 → 공식 문서에 없음(확인 불가), Phase 2는 보고서 업로드로 검토
- [ ] 마케터에게 협조 요청: 매주 보고서 다운로드·업로드(5분 이내) 가능한지, 일정 합의
- [ ] 마케터가 광고주센터에서 내려받을 보고서 종류 확인 (소재 단위 성과가 나오는 보고서)
- [ ] **샘플 보고서 1개 확보** (숫자는 가려도 됨). 컬럼 헤더와 파일 형식 확인
  - [ ] 소재 ID, 광고 상품 구분, 노출수, 클릭수, 광고비, 전환수, 전환매출, 평균 노출 순위, 기간이 모두 있는지
  - [ ] 쇼핑검색 소재가 상품 단위인지 광고그룹 단위인지
  - [ ] 파워링크 이미지 확장소재 성과가 소재 단위로 나오는지
- [ ] 드라이브 업로드 폴더 만들고 마케터에게 공유
- [-] 마케터에게 API 키 발급 요청 (불가 판정, 나중에 재요청 가능)
- [-] 읽기 전용(`READ_ONLY`) 구성원으로 API 키 발급이 되는지 확인

**완료 조건:** 샘플 보고서의 컬럼이 확정됨

## 1단계: 시트와 설치

- [~] 구글 시트에 5개 탭 생성 (`setupSheets`), 설정 기본값 입력
- [~] 스크립트 전용 탭 보호 (원본·판정·알림_로그)
- [~] 메뉴 `네이버 광고` 동작
- [ ] 실제 시트에 코드 붙여넣고 `setupSheets` 실행해 확인 ([SETUP.md](SETUP.md))
- [-] 스크립트 속성에 API 키 저장 (`setCredentials`)
- [-] HMAC-SHA256 서명, 캠페인 목록 조회 테스트 (`testListCampaigns`)

**완료 조건:** 5개 탭과 헤더가 만들어짐

## 2단계: 수집 (보고서 업로드)

- [ ] 보고서 컬럼 → `네이버_원본` 컬럼 매핑표 작성 (샘플 확보 후)
- [ ] 드라이브 폴더에서 새 파일 찾기, CSV/엑셀 읽기
- [ ] 필수 컬럼 검증, 불일치 시 오류 메일
- [ ] 기간(월~일)과 광고 상품 판별
- [ ] 원본 탭에 기록, 같은 기간·소재 ID는 덮어쓰기 (`upsertRawRows_` 재사용)
- [ ] 처리한 파일을 `처리완료` 폴더로 이동
- [ ] 월요일에 새 파일이 없으면 안내 메일
- [ ] 설정 탭에 `수집 방식`, `보고서 폴더 ID` 추가
- [~] (API 방식 코드 작성됨, 휴면) `Collect.gs` 수집 함수
- [-] (API 방식) `0단계` 조사 결과 반영: 이미지 확장소재 타입 `POWER_LINK_IMAGE`, `timeIncrement=allDays`, 캠페인 유형별 stats 호출 분리

**완료 조건:** 업로드한 보고서의 소재별 노출·클릭이 원본 탭에 쌓임

## 3단계: 매핑과 판정

- [~] 지표 계산: CTR, 전환율, CPC, ROAS, 평균 노출 순위
- [~] 광고 상품별 최근 4주 기준선 CTR (합산 방식)
- [~] 최소 노출 1,000 미만 → 데이터 부족
- [~] 성공 / 보통 / 개선 필요 판정 (경계값 ±20% 포함)
- [~] 평균 노출 순위 비교, 순위 영향 표시 (순위 값이 0이면 비교 안 함)
- [~] 3주 추이와 소재 피로 판정
- [~] 교체일 기준 작업물 ID 분리
- [~] 미매핑 소재를 매핑 탭에 자동 추가 (작업물 ID 빈칸), 최신 주 매핑률 계산
- [~] 광고 상품별 소재 5개 미만이면 알림 끔
- [~] 파워링크 텍스트 소재는 판정 제외
- [~] 설정 탭 값으로 기준 읽기 (`parseSettings_`)
- [x] 판정 계산 단위 테스트 통과 (`node tests/verdict.test.js`)
- [ ] 실제 시트에서 `판정 실행` 메뉴로 확인
- [ ] 기존 쇼핑검색 소재부터 매핑 입력 (디자이너)
- [ ] 기존 성과 기록 템플릿의 배너 시트가 판정 탭 값을 작업물 ID로 불러오도록 연결

**완료 조건:** 판정 탭 자동 갱신

## 4단계: 트리거와 알림

- [ ] 수집·판정·알림 함수 분리, 시간 트리거 등록 (월요일, 순서: 수집 → 판정 → 알림)
- [ ] 판정 시 최신 주 데이터가 지난주인지 확인. 아니면 판정·알림 중단 (이전 주 데이터로 돌리지 않음)
- [ ] 알림 대상: 판정 탭의 `알림 유형`이 비어 있지 않은 행 (최신 주만)
- [ ] 알림 메일 본문: 제목, 소재별 한 줄, 규칙 기반 진단, 미매핑 목록, 판정 탭 링크
- [ ] MailApp 발송, 수신자는 설정 탭에서 읽기
- [ ] 수집 실패·미업로드 시 오류 메일 + `알림_로그` 기록
- [ ] 발송 내역을 `알림_로그`에 기록
- [ ] 한 주 동안 테스트 수신자에게만 발송해 검증

**완료 조건:** 월요일 알림 수신

## 5단계: AI 개선안

- [ ] Claude API 키를 스크립트 속성에 저장
- [ ] 프롬프트: 입력(작업물 ID, 광고 상품, CTR·전환율·순위, 3주 추이, 규칙 기반 진단), 출력(원인 가설 1~2문장, 수정 제안 3개, A/B 테스트 1개, 주의 1문장)
- [ ] 순위 영향 표시 소재는 주의 문장에 "입찰·순위 확인 먼저" 포함
- [ ] 알림 대상 소재만 호출, 설정 탭의 AI 사용 여부 확인
- [ ] 결과를 `알림_로그`에 전문 저장
- [ ] API 오류 시 AI 개선안 없이 알림은 정상 발송

**완료 조건:** 알림에 AI 개선안 포함

## 6단계: 운영 점검

- [ ] 운영 4주 후 성공 기준 4개 점검
  - [ ] 마케터 주간 수동 작업 5분 이내
  - [ ] 수집 성공 4주 중 4회
  - [ ] 매핑률 90% 이상
  - [ ] 알림 소재 중 1건 이상이 교체 또는 A/B 테스트로 이어짐
- [ ] 판정 기준값(±20%, 최소 노출, 순위 차) 조정
- [ ] 마케터에게 결과 공유, Phase 2(성과형 디스플레이, 보고서 업로드 방식) 결정
- [ ] 키 확보가 가능해졌다면 API 방식 전환 검토

## 리스크 확인 (상시)

- [ ] 마케터의 주간 업로드가 빠지지 않는가 (미업로드 안내 메일 동작)
- [ ] 보고서 형식이 바뀌어도 컬럼명 기준으로 읽는가
- [ ] CTR이 순위·키워드에 흔들리는 문제: 순위 영향 표시와 같은 광고 상품끼리 비교가 동작하는가
- [ ] 매핑 누락: 미매핑 목록이 알림 메일 하단에 포함되는가
- [ ] 개인정보: 고객 정보 없이 광고 성과 수치만 저장하는가
