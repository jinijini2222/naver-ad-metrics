# 개발 과정 체크리스트

[PRD](PRD.md) 기반. 2026-11-02에 마케터가 **네이버 검색광고 API 키만 발급 가능**하다고 확인해, API 방식으로 진행한다. 키가 필요한 실제 호출 검증은 키를 받은 뒤로 미루고, 나머지를 먼저 개발했다.

**표기**: `[x]` 완료 · `[~]` 코드 작성·가짜 환경 테스트 통과, 실제 시트/API 미검증 · `[ ]` 미착수 · `[-]` 보류(대안 방식)

테스트: `node tests/verdict.test.js`, `collect.test.js`, `alert.test.js`, `ai.test.js`, `mapping.test.js`, `banner.test.js`, `e2e.test.js` (모두 가짜 환경, 네이버·Claude 호출 없음). `e2e`는 가짜 스프레드시트로 초기화 → 데모 → 판정 → 알림 → 오류 경로 → 삭제를 실행한다.

## 3단계: 매핑과 판정

- [~] 지표 계산: CTR, 전환율, CPC, ROAS, 평균 노출 순위, 기준 전환율

- [~] 최소 노출 미만 → 데이터 부족
- [~] 성공 / 보통 / 개선 필요 판정 (경계값 ±20% 포함)
- [~] 순위 영향 표시 (순위 값이 0이면 비교 안 함)
- [~] 3주 추이와 소재 피로
- [x] 매핑 탭 입력 규칙 문서화 → [MAPPING_RULES.md](MAPPING_RULES.md)
- [~] 매핑 탭 입력 제한(광고 상품 드롭다운, 날짜 검사), 작업물 ID 빈 행 강조, 시트 시간대 서울
- [~] 매핑 점검 (메뉴 5-1): 날짜 형식, 기간 겹침·공백, 작업물 ID 규칙
- [~] 교체일 기준 작업물 ID 분리, 교체 후 새 작업물 미등록 감지
- [~] 미매핑 소재를 매핑 탭에 자동 추가, 최신 주 매핑률 계산
- [~] 광고 상품별 소재 5개 미만이면 알림 끔, 파워링크 텍스트 판정 제외
- [~] 설정 탭 값으로 기준 읽기
- [~] 데모 데이터 → 판정 → 알림 미리보기 흐름 (메뉴 9, 5, 7), 가짜 스프레드시트로 검증
- [ ] 실제 시트에서 데모 데이터로 `판정 실행` 확인 후 데모 삭제 ([SETUP.md](SETUP.md) "키 없이 해 볼 순서")

- [~] 성과기록_배너 임시 템플릿: 판정 탭 최신 주를 작업물 ID별로 자동 채움, 조치 기록 → [PERFORMANCE_LOG.md](PERFORMANCE_LOG.md)
- [ ] 기존 성과 기록 템플릿이 생기면 컬럼 대응 변경

**완료 조건:** 판정 탭 자동 갱신

## 4단계: 트리거와 알림

- [~] 시간 트리거 설치 (`installTriggers`: 월 09:00 수집, 10:30 판정, 11:00 알림)
- [~] 지난주 데이터가 없으면 판정·알림을 중단하고 오류 메일 (이전 주 데이터로 판정 금지)
- [~] 알림 대상: 최신 주의 `알림 유형`이 있는 소재
- [~] 메일 본문: 제목(`9/14~9/20` 형식), 소재별 한 줄, 규칙 기반 진단, 미매핑 목록, 판정 탭 링크, HTML 이스케이프
- [~] 수신자는 설정 탭에서 읽기, 알림 대상이 없으면 발송하지 않고 로그만
- [~] 오류 메일 + 알림_로그 기록 (`notifyError_`)
- [~] `previewAlert`: 메일을 보내지 않고 내용만 확인
- [ ] 실제 시트에서 데모 데이터로 `알림 미리보기`, 본인 주소로 `알림 발송` 검증
- [ ] **키 필요:** 월요일 자동 실행 한 사이클 확인 (수집 → 판정 → 알림)

**완료 조건:** 월요일 11:00 알림 수신

## 5단계: AI 개선안

- [~] Claude Messages API 호출 (`Ai.gs`, UrlFetchApp). 모델 `claude-opus-5-5`, effort `medium`, 금지 파라미터(temperature·사고 비활성화·prefill·강제 tool_choice) 미사용
- [~] 프롬프트: 입력(작업물 ID, 광고 상품, CTR·전환율·순위, 3주 추이, 규칙 진단), 출력(원인 가설, 수정 제안 3개, A/B 테스트 1개, 주의 1문장)
- [~] 순위 영향 소재는 "입찰·순위 확인 먼저"를 프롬프트로 요구하고, 빠지면 코드가 보강
- [~] 알림 대상만 호출, 설정 탭의 AI 사용 여부 확인
- [~] 거절·오류·키 없음이면 AI 없이 알림 정상 발송
- [~] 서버 측 폴백(`fallbacks: "default"`) 사용, 400이면 폴백 없이 1회 재시도
- [x] 결과를 알림_로그에 전문 저장
- [ ] Claude API 키 입력 (`setClaudeApiKey`), 실제 호출 1회 확인 (응답 형식·비용)

**완료 조건:** 알림에 AI 개선안 포함

## 6단계: 운영 점검
